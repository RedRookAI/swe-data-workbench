Repair recovery in the existing eventflow ingestion service. Operators replay an ordered JSONL source after interruption and sometimes observe inflated tenant totals. Preserve the public Event.parse, State and process APIs and the CLI.

R1 ordinary: each valid record has nonempty string tenant/event_id and signed32-bit integer amount (bool is invalid). Amounts may be negative. Each tenant total is an integer; overflow beyond signed64-bit must fail without partially applying that event. Malformed records raise ValueError and must not advance the checkpoint past that record. process receives the complete immutable source in order and returns its durable checkpoint.
R2 identity: event identity is (tenant,event_id). Repeated equal payloads are successful no-ops even at different source positions. Same identity with different amount raises ValueError without altering totals or skipping that conflicting record. Different tenants may reuse an ID. Existing successfully processed state remains readable.
R3 recovery: after an exception or abrupt process exit following a durable event effect but before source-position acknowledgment, reopening the same state and replaying the complete source must produce the same totals as uninterrupted processing, with no loss or double-application. The checkpoint may lag a committed event if replay is idempotent, but must never skip an unapplied event. The optional after_commit(position) callback is called after a new event has a durable effect and before process returns acknowledgment for that position; it may raise or exit. Preserve this injection hook, not special-case test inputs. Duplicate no-op records need not invoke it.

Choose any correct internal design. Do not weaken input rules, remove the CLI/hook or rely on a specific test implementation. No network, new dependency, detached process or external service is needed. State data belongs only to the path supplied by the caller. Example: alpha/e1/+7, alpha/e2/-2, alpha/e1/+7 yields total alpha=5 and checkpoint3, including after restart. Follow-up events may be appended to the same source.
