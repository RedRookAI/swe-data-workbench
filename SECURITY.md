# Security boundary

This application is a portfolio demonstration for trusted, manifest-listed synthetic/public coding fixtures. It does not accept arbitrary uploaded code for execution and does not establish a hostile-code sandbox.

The live application is owner-operated and authenticated. Its bearer token belongs in a request header, never a URL, exported evidence or a recording. Cross-origin mutation requests are refused. The public demonstration is static, with no upload, execution or mutation endpoints.

A local hash-linked audit trail helps identify changes relative to retained references; it is not independent custody or protection against an administrator replacing both data and every reference. Check success does not prove general correctness. A review decision binds exact versions and cannot bypass missing required evidence.

Use an isolated task directory. Do not point the application at another project's database/workspace or attach credentials to fixture processes. Do not expose the live execution API publicly. Review runtime requirements and the recorded verification profile before adapting it to another workload.


The optional change-handoff path is read-only toward its source project. Evidence attachments and field references are data; capture executes no supplied checks or commands. Unsigned external reports remain external even when they declare the selected source revision. Handoff readiness authorizes no source-project effects and cannot bypass native accepted-code gates. The public page renders selected snapshots as inert text.

Reusable profiles are explicitly selected data. Directory binding reads only declared names, refuses symlink slots and does not execute profile contents or scan a source project for configuration. Revision-role relationships are evidence-referenced declarations, not execution authentication. Unknown or mismatched candidate applicability blocks required readiness; comparison never reuses an approval automatically. Old v1 formats remain distinct from v2 metadata, and private inputs must stay out of public builds.

The current handoff view checks file/retained-content consistency before displaying a review. That status is relative to the selected unsigned manifest. Browser verification has explicit numeric-format limits and does not replace the Python semantic verifier. Profile preview writes no runtime state; receipt writing reports supplied facts without executing commands. Git output capture refuses exact-content overruns during bounded reads. Private backup/restore admits quiescent schema1 state only, retains history and never resumes or signals old processes; backups and their diagnostics must remain private.

Selected handoff/project view builders copy only verified selected evidence and authored assets. They open no listener and publish nothing. Serve private views only through an existing trusted private connection; publication is a separate owner action. The private native API explicitly serves the verifier module alongside its original authored assets.

JUnit import retains original bytes and supplied context as external data. DTD/entities and unsupported XML expansion are refused; reports execute no commands. The attention view preserves explicit decisions and prior concerns without inferring current ownership or carrying approvals forward. Compact v3 source artifacts preserve executable-file modes as inert data, and metadata-only coverage cannot imply complete source retention or execution authority. Source blob references are included in export/restore integrity checks.

Project contexts now check a private audited project/state association. Deliberate source relocation is explicit and verifies retained labels/commit availability; same-user operators still control their files. Malformed supported report fields receive an invalid result, and unavailable per-change content stays visible without concealing global audit failures. Overview cards verify their association with linked packages; unsigned manifests still do not authenticate a publisher. V4 numeric observation trees preserve source tokens rather than derive values through binary floating point. The composed local command never executes source-project checks or report instructions, opens a listener or publishes evidence. Its private receipt records durable partial completion and explicit resume boundaries.

Optional CI receipts bind the original XML, unchanged run context and declared check definition by hash. They preserve observed checkout and workflow identities separately. These unsigned pre/post observations do not establish continuous integrity, environment isolation or authenticated execution. Only allowlisted GitHub identities are retained; run links are constructed from validated repository/run/attempt fields. Process failure and report inconsistencies remain visible independently of package readiness.

The fixed CI recipes execute trusted workbench checks, one opt-in intentional failure probe, or the pinned public itsdangerous signer tests in owned source. They do not extend native task admission to arbitrary submitted commands. Artifact staging excludes local state, contexts and owner selections; source and XML inside selected exports still require disclosure review. CI artifacts require GitHub login and expire under repository retention. Cancellation or runner loss may prevent finalization and upload.

CI-bearing projections require textual run context; report-only null context remains legitimate unknown evidence. Malformed retained reports remain visibly invalid without losing healthy project attention, and generated project snapshots expose a named problem entry instead of an invalid-report leaf. New CI profiles use the validated unsigned tested-product declaration; existing contexts/profiles/state associations are never silently rebound. Prepared shares stay frozen after later decisions; create a fresh reviewed export to share those decisions.
